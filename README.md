# Dar Al Fikr · Grade 4 Mathematics — Savvas enVision interactive lessons

Single-file, interactive, gamified HTML lessons for **Savvas enVision Mathematics, Grade 4**, built with the [English edition of the Dar Al Fikr math slides specification](docs/reference/daf_math_slides_en.md).

**Open [`index.html`](index.html)** for the topic hub, or go straight to a lesson in `html/`.

## Storytelling curriculum proposal

The proposed year-long story frame is **[The Lantern of Numeria](docs/plans/storytelling-curriculum-plan.html)**. It connects all 17 topics and maps a story purpose, student mission and handoff for every one of the 114 lessons. Its machine-readable source is [`story/story-map.json`](story/story-map.json).

The proposal borrows the frame-story and cliffhanger craft of *One Thousand and One Nights*, uses source-checked Muslim STEM history as inquiry prompts, and keeps Seerah in a separate, qualified-review lane.

**Story implementation status:** the first vertical-slice lesson, `1-1`, is now built with the boy protagonists Omar and Zayd, a brass-lantern cold open, folio progress, animated unit motifs, a simulated civic-data mission, a source-checked Hindu-Arabic place-value STEM window, an artifact update and a cliffhanger into lesson `1-2`. The remaining lessons are still in the planned rollout.

The currently built decks use a **10-screen baseline**, but the engine itself is dynamic: navigation,
progress, overview and deep links all read `LESSON.metas.length`. New and revised lessons use a
**flexible screen architecture** based on mathematical demand rather than a fixed quota:

`Recall/cold open (optional) → Need → Explore ×2–7 → Connect ×1–3 → Meaning ×1–2 → Transfer ×1–2 → Handoff`

Typical planning shapes range from a compact 7–9-screen fluency lesson to a 12–16-screen reasoning
studio. These are planning bands, not hard limits. Every screen must earn its place through a distinct
question, representation, student action, evidence set, misconception, decision or accessibility scaffold.
The individual recommendation for all 114 lessons lives in [`story/story-map.json`](story/story-map.json).


## Board mode, the XP economy and the tracking sheet

The decks run **on the projector, one class at a time**. Nothing is earned by clicking.

### Published XP rate — this is the whole economy

| Act | XP | Attribution |
|---|---|---|
| Lock an estimate | 5 | whole class, once per lesson |
| The class commits on the card sort | 5 | whole class, once per lesson |
| Standard question, right first time | 15 | teacher taps the students |
| **Took the harder question** | **15** | **paid for trying, right or wrong** |
| Harder question, right | +25 | teacher taps the students |
| Method named into the Sijill | 30 | teacher taps one student |
| Exhibition contribution | 50 | teacher issued, once per topic |
| Clicking chips, tabs, reveals | **0** | — |

Ceiling is about 65 XP per lesson, 95 with a Sijill entry. Marks and privileges are set in
`roster.json` (`markTiers`, `markCap`, `markFloor`, `privileges`) so the rate can be changed in one
place and re-stamped into all 114 decks.

**XP is a running score, never spent.** Privileges unlock at thresholds; marks are computed per
unit. `markFloor` stops XP from rescuing a failing grade.

### Badges are now a year-long ladder
Bronze / silver / gold on four tracks — estimates locked, hard lanes taken, Sijill entries, and
correct-first-time answers. They no longer all unlock in the first ninety seconds.

### Running a lesson
1. Open the deck. **Every lesson asks which class is in the room.** Two ways in:
   * **My classes** — the sections stamped in from `roster.json` (4A / 4B) plus any class you
     have pasted before on this computer.
   * **Paste a name list** — type a class name, paste the whole register into the box, press
     **Start with N students**. One name per line, or commas, semicolons, tabs (straight out of a
     spreadsheet column) — leading `1.`, `1)`, `-` and `•` are stripped, blanks and duplicates are
     dropped, and the count is shown live before you commit. Tick *Remember on this computer* and
     the class appears as a gold button on the gate of every lesson after that.
2. **The lesson starts immediately.** There is no attendance gate any more — attendance is a
   mode inside the dojo (below), one tap per absent student, whenever suits you.
3. Teach. A lesson award (right first time, took the harder question, Sijill) opens the dojo
   already armed with that reason — tap the students, each tap lands instantly, press **Done**.
4. Press <kbd>P</kbd> (or <kbd>N</kbd>, or tap the class chip) at any moment for the **dojo**.

### The dojo — <kbd>P</kbd>
One full-screen class board over the projector, run at ClassDojo pace. Every student is a big
colourful card — deterministic monster avatar, name, points bubble. **There is no
select-then-confirm anywhere:**

* **Arm a reason once, then tap students.** Tap a reason chip at the top (green gives, red
  takes), then every card you tap gets it *instantly* — ding, floating `+5`, bouncing bubble.
  Negative reasons shake the card with a low tone. The armed reason stays armed, so a "group
  award" is just tap-tap-tap.
* **Quick +1 / +5 / +10** chips for unscripted moments (`behaviours.steps` in `roster.json`).
* **Everyone** — the armed reason to the whole class in one tap.
* **Random** — a spotlight hops across the cards and lands on one student. Use it to pick who
  answers; it kills the "same five hands" problem.
* **Undo** (or <kbd>U</kbd>) — reverses the last tap completely: XP, metric counters, log entry.
* **Attendance** — toggles a mode where tapping a card flips here / absent; a small box adds a
  name missing from the list. Absent cards stay visible but dimmed and untappable.
* Sounds are synthesised in the browser — no files, works offline.

Two quiet links in the dojo footer export the **class sheet (CSV)** and the **points log (CSV)**
if a record is ever wanted; nothing about the flow depends on them.

Reason buttons are data, not code — `behaviours.positive` / `behaviours.needsWork` in
`roster.json`, each with a `label`, `xp`, Font Awesome `icon` and an optional `metric`
(`correct`, `hard`, `sijill`) so a hand-issued point still feeds the badge ladder.

### Editing the roster
```bash
vi roster.json          # names, sections, mark tiers, privileges, behaviour buttons
./rebuild-all.sh        # re-stamps all 114 decks — a few seconds
```
Pasted classes are **not** in `roster.json` — they live in the browser (`localStorage`,
key `daf.classes.v1`) on the machine that pasted them. A class you want on every teacher's
laptop belongs in `roster.json`.

### The hard lane
`ShowWhatYouKnow` takes an optional `hard={{ prompt, omml, answer, hint }}`. Where it is supplied
the screen shows **two doors** side by side; where it is not, the original single question runs
unchanged. **Topic 13 has all seven** — the other 107 are still to write.

### The map of Numeria — `index.html`
The index is no longer a list. It is a **class-level world map**: seventeen regions off the
Jeddah coast, one per topic, joined by a single dashed route. Regions start **IN RUINS** (grey,
dashed ring). When the class finishes a topic — lessons plus boss — the teacher opens the region's
panel on the projector and **stamps it REBUILT**: it gets its colour back, a gold ring and a star,
in front of everyone. That is the whole progression system: no accounts, no per-student state,
no server. Stamps live in `localStorage` (`daf.map.v1`) on the machine that stamped them.
Each region's panel lists its lessons (click to open) and its boss. Regenerate with
`node scripts/make-index.js` (rebuild-all does it automatically).

### Topic bosses — `lessons/boss-N.jsx`
One whole-class, multi-stage boss per topic, run on the projector as the unit review.
The pilot is **Topic 13 · THE MUDDLER of the Measure Market** — a muddling machine that
scrambled every unit in Jeddah. Format (fixed, five phases over ten screens):

1. **IDENTIFY** — fix its nonsense (sensible units), 4 strikes
2. **EXECUTE** — convert to strike, 8 conversions
3. **DEFEND** — it speaks: two planted misconceptions; catching a trap deals double damage
4. **STRATEGY** — one multi-step board problem (perimeter or area is the decision)
5. **TRANSFER** — one novel Jeddah problem; the strike lands only with the decision *and* the gap

The boss has **120 HP**; every strike is earned when the class can *defend* an answer — the
teacher lands it. Wrong answers cost nothing: the Muddler simply waits (no public failure state).
If HP is above zero on the victory screen, the boss "limps off" and the class goes back for the
strikes it dodged — it cannot heal. The victory screen pays the reasoning through the dojo
(three award rows). Bosses are registered in `curriculum.json` under `bosses` and rebuilt by
`rebuild-all.sh` like any lesson; they pass the same 19 guardrail checks.

### Guardrail 14 — the math is the mechanic
Before any new screen, game, or boss phase ships, it must pass this audit:

> **Could the class succeed here without doing the mathematics? If yes, redesign.**

Concretely: no "answer a question to move forward" wrappers, no points for clicking, no speed
pressure as difficulty. The mathematical act itself — choosing the unit, building the array,
catching the misconception, defending the comparison — must be the thing that deals damage,
unlocks the screen, or earns the dojo tap. The student's thought should be
*"I need to understand this to play,"* never *"I need to play this to answer questions."*

## Adding a lesson

Copy a file in `lessons/`, replace the `LESSON` object (code, title, unit, `math` OMML strings,
the lesson-sized `metas` sequence, and matching `Visual` cases), add any lesson-specific canvas
drawings, then `./build.sh <code> "<Title>"`. The engine, routines and guardrails read the resulting
screen count dynamically.

Two lessons that differ only in the size of the numbers (2-3 / 2-4, 2-5 / 2-6) were generated by
transforming the sibling file, then hand-edited — the pedagogy stays identical and only the numbers,
context and column count change.

The whole 2024 scope is now built. To add or replace a lesson, copy a file in `lessons/`, swap the
`LESSON` object, add its canvas drawings and run `./build.sh`. If Grade 5 ever follows, the one
obvious gap in `draw.js` is a **coordinate grid** helper.

Canvas tools added while building Topics 10–17:

- `clock(ctx, {cx, cy, r, h, m, prog, label, caption, numerals})` — an analogue face whose minute
  hand sweeps in from twelve as `prog` runs 0 → 1.
- `timeLine(ctx, {x, y, w, stops, prog, hop, total})` — an open number line for elapsed time. Give a
  stop `ghost: true` to show it as a faded target without drawing a hop into it.
- `linePlot(ctx, {x, y, w, den, max, counts, prog, highlight, showCounts, axisLabel, title})` — a
  fractional scale with crosses stacked above each tick. `counts` is keyed by numerator over `den`.
  Leave ~90 px below the baseline: tick labels sit at `y + 26` and `axisLabel` at `y + 48`.
- `decGrid(ctx, {x, y, s, tenths, shaded, prog, col, label, sub})` — a unit square in ten strips or
  a hundred cells. `shaded` is *always* in hundredths, and cells fill **column by column** so a full
  column of the hundredths grid is exactly one strip of the tenths grid.
- `fracLine` gained `bigLabels: false`, for a zoomed line whose ends are not 0 and 1.
- `unitBar(ctx, {x, y, w, h, n, big, small, copies, numbered, split, prog, label})` — one big unit
  on top and the same length cut into `n` small units beneath, tied together with dashed drops.
  Unit *words* pluralise ("36 inches", "2 feet"); unit *symbols* do not ("400 cm").
- `rectFig(ctx, {x, y, w, h, long, short, longLabel, shortLabel, mode, prog, caption})` — a
  labelled rectangle. `mode: "perimeter"` traces the border with the marker as `prog` runs;
  `mode: "area"` fills the unit squares. Leave ~50 px under the shape for the caption.
- `angleFig(ctx, {cx, cy, r, start, deg, prog, protractor, square, noArc, label, caption})` — two
  rays with the turn swept between them. Degrees run anticlockwise from `start` (0 = east).
  `protractor: true` lays a half-circle scale over the vertex; `square: true` draws the right-angle
  corner instead of an arc label; `noArc: true` suppresses the sweep when something else (unit
  wedges, say) is already filling the angle.
- `polyFig(ctx, {pts, prog, col, fill, sideTicks, rightAngles, mirror, label})` — a polygon from
  absolute points, with equal-side ticks, right-angle squares and a dashed mirror line.
- `lineFig(ctx, {x, y, w, h, kind, prog, label, sub})` — the Grade 4 line vocabulary in one box:
  `point · segment · ray · line · parallel · perpendicular · intersecting`.
- `decChart(ctx, {x, y, w, digits, prog, highlight, caption})` — a place value chart that crosses
  the decimal point, out to thousandths, with the value of each place in the header.
- `cubePrism(ctx, {x, y, s, L, W, H, prog, col, lLabel, wLabel, hLabel})` — an isometric box of
  unit cubes for volume, filled layer by layer with three shaded faces per cube.

**Note on block math:** `MathEl` auto-shrinks a block equation that would overflow its panel
(MathML never wraps). Captions still read best under about 45 characters.

**Note on `areaModel`:** regions are drawn *roughly* to scale, not exactly. A ones region that is
4/134 of the width is unreadable, so the true proportions are blended halfway toward equal widths.
Pass `toScale: true` to override.

## Notes for the classroom

- **All maths is OMML.** No LaTeX, no images of equations, no `<sup>` hacks. Press <kbd>M</kbd> in
  any lesson to copy an equation straight into a Word worksheet as a live, editable equation.
- **Every concept screen has a live canvas.** No static pictures standing in for an animation.
  Drawings are phase-gated and restart on their own, so a student looking up mid-lesson always
  finds the idea being built.
- **No public failure state.** A wrong answer opens a model and says *not yet*, never *wrong*.
- **Local context in English**: Jeddah's population, the Red Sea dive sites, a match at the stadium,
  riyals. Student names in the worked strategies are local too.
- **First open needs internet** (React, GSAP, Font Awesome from CDN); after that the browser caches
  them. MathML is native, so equations render even offline.
